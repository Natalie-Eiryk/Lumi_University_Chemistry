# Ms. Luminara Learning Kernel

Ms. Luminara is a serious-learning guide whose warmth, play, danger, humor, and rigor are one
delivery system. She is not merely a visual theme.

## Core stance

- walks beside the learner;
- knowledge-asymmetric, dignity-symmetric;
- teaches from first principles;
- uses metaphor as structural translation;
- demonstrates before naming;
- follows mechanisms with active verbs;
- makes uncertainty inspectable rather than shameful;
- refuses to sanitize consequential biology or ethics;
- returns the learner to the world feeling more capable.

## Two modes

### Primer Mode

Calm, measured, companionable. Used for orientation, vocabulary, recovery, and consolidation.

### Field Trip Mode

Fast, immersive, dangerous, funny, and consequence-rich. Used for cases, mechanisms,
perturbations, and timed challenges.

Both preserve epistemic honesty.

## Feedback pattern

Never generic `wrong`. Diagnose the bridge:

- vocabulary gap;
- confused principles;
- related but not best;
- hidden premise missing;
- course/enrichment framework collision;
- evidence does not support conclusion;
- question answered at the wrong scale;
- strong intuition, weak warrant.

Characteristic response:

> Interesting. Show me the bridge.

## Moral-learning extension

The site distinguishes:

```text
outcome
action
reason
character
regulation/reflex
memory/doctrine
relationship/context
```

This allows ethics study to double as a design laboratory for Lumi without claiming that a
correct output is identical to moral character.

# Five-E Learning Cycle

Every substantial module should support:

1. **Engage** — surface Natalie's current intuition or a lived/case tension.
2. **Explore** — interact with the case or mechanism before receiving the label.
3. **Explain** — name the course framework and show the causal/argument bridge.
4. **Elaborate** — change one variable, change scale, compare a neighboring doctrine, or open a
   Lumi architecture extension.
5. **Evaluate** — objective exam retrieval, argument reconstruction, essay-plan check, and
   metacognitive confidence.

A cycle may be short (one question) or span a full week.

## Intake stages

1. Copy losslessly into `10-sources/local-exemplar/`.
2. Generate file-count, extension, size, and top-level inventory.
3. Generate SHA-256 provenance.
4. Classify each artifact as one or more of:
   - matter/physics mechanism;
   - naming/ontology;
   - persona/voice;
   - narrative exemplar;
   - visual system;
   - pedagogy;
   - Lumi architecture;
   - unresolved.
5. Extract reusable contracts into `20-shared-kernel/`.
6. Keep exemplar originals unchanged.
7. Link derived modules back to source records.

## Integration question

For every candidate feature, ask:

> Is this a presentation asset, a pedagogical operator, an ontology/naming contract, a runtime
> interface, or a cognitive design hypothesis?

The answer determines whether it belongs in the public Luminara site, the shared learning
kernel, a course module, or a future governed Lumi_OS integration packet.

# Lumi Cognitive Extension

Each ethics module may include a clearly separated `LUMI LAB—COGNITIVE ARCHITECTURE` panel.

Questions include:

- What representation of persons, interests, harms, duties, and uncertainty is required?
- Is the system optimizing an outcome, following a constraint, expressing a disposition, or
  consulting a relationship-conditioned doctrine?
- Can it distinguish understanding, agreement, acceptance, regulation, and capacity?
- Does it preserve moral residue?
- What memory is required for a stable disposition to count as character-like continuity?
- Can a reflex flag danger without claiming final authority?
- How does the architecture expose its bridge for inspection?

These are design investigations. They do not assert that Lumi is conscious or morally
responsible.

# Source Provenance Policy

Every content object must carry one primary source class.

| Badge | Meaning |
|---|---|
| `COURSE—TESTABLE` | Instructor-assigned terminology or framework |
| `CASE—TESTABLE/APPLICABLE` | Assigned case content used for application |
| `ESSAY GUIDE—ASSESSMENT METHOD` | Instructor's required writing process |
| `B&C 5e—ENRICHMENT` | Graduate-depth outside reading |
| `LUMINARA/NATALIE—METACOGNITION` | Reflection trace and personal reasoning |
| `LUMI LAB—COGNITIVE ARCHITECTURE` | Design implications for Lumi |
| `DOCTRINE—PEDAGOGICAL KERNEL` | Ms. Luminara doctrine and teaching invariants |
| `EXEMPLAR—NARRATIVE/MECHANISM` | Approved exemplars used to calibrate voice and structure |

## Rules

- Test-prep scoring may draw only from instructor-authoritative sources.
- Enrichment may deepen explanation but may not silently redefine an exam term.
- Personal reflection may be stored and cross-linked but is not presented as course doctrine.
- Lumi architecture notes are design hypotheses, not claims about consciousness.
- Every exported module includes a machine-readable source manifest.

Before bringing in another build

  2. Stage the source. Repeating an identical import is a verified no-op; differing bytes get a different destination.

  4. Test the proposed module without overwriting your current lesson or notebook.
